# 候选聚合解决方案

## 问题背景

当项目有 60+ 个设备块时，绑定候选可能产生 400+ 条结果，导致：
1. 用户难以快速定位需要复核的候选
2. 同名块的多个候选分散显示，无法批量操作
3. 低质量候选淹没高置信度候选

## 解决方案

### 1. 按块名聚合（Block-Level Aggregation）

**核心思路**：将相同 `block_name` 的候选聚合为一组，用户可以：
- 一眼看到每个块有多少候选
- 快速确认/忽略整个块的所有候选
- 查看每个块的最佳匹配建议

**实现位置**：`app/binding/candidate_aggregator.py`

**聚合逻辑**：
```python
# 按 block_name 分组
block_groups = {}
for candidate in candidates:
    block_key = eo.block_name or eo.layer_name
    if block_key not in block_groups:
        block_groups[block_key] = AggregatedCandidate(...)
    block_groups[block_key].candidates.append(candidate)
```

### 2. 相似度加权排序（Similarity-Weighted Sorting）

**核心思路**：块名与 BOQ 描述相似度高的候选优先展示，因为：
- 用户手动关联时，相似度高的更容易确认
- 相似度高意味着规则/LLM 匹配质量好
- 减少用户认知负担

**相似度计算**（`calculate_name_similarity`）：
1. **整串相似度**（权重 0.6）：块名与 BOQ 描述的文本相似度
2. **关键词重叠**（权重 0.3）：分词后的关键词重叠比例
3. **编号匹配**（权重 0.1）：如 AL-01 ↔ 配电箱 AL-01

**排序规则**：
```python
sorted_groups = sorted(
    block_groups.values(),
    key=lambda g: (-g.similarity_score, -g.max_confidence, -g.total_count)
)
```

### 3. UI 优化（Narrow Panel Button Layout）

**问题**：绑定工作台右栏较窄时，"定位/忽略/确认" 按钮显示不全

**解决方案**：
1. **紧凑型按钮**：最小宽度 45px，最大宽度 60px
2. **主次分明**："确认" 按钮使用青色背景，"忽略" 使用灰色
3. **按钮行独立**：按钮行与建议绑定行分离，避免挤压

**实现位置**：`app/ui/binding_workbench.py`

## LLM 推荐候选聚合方案

### 方案 A：块级批量确认

**适用场景**：同名块的所有候选置信度都很高（≥0.95）

**流程**：
1. 聚合同名块的所有候选
2. 计算块级置信度（所有候选置信度的加权平均）
3. 块级置信度 ≥ 0.95 → 提示用户批量确认
4. 用户确认后，该块的所有候选一次性写入 mapping

**优势**：减少重复操作，提升效率

### 方案 B：相似度优先展示

**适用场景**：用户需要快速找到高质量候选

**流程**：
1. 按相似度降序排列块组
2. 相似度 ≥ 0.7 的块组高亮显示
3. 每个块组只显示前 3 个最佳候选
4. 用户可展开查看完整候选列表

**优势**：减少信息过载，聚焦高质量候选

### 方案 C：智能推荐排序

**适用场景**：需要 LLM 辅助决策

**流程**：
1. 聚合同名块的所有候选
2. LLM 分析块名、图层、规格等特征
3. 为每个块组生成推荐置信度
4. 按推荐置信度排序展示

**优势**：利用 LLM 理解语义，提升推荐质量
