# 绑定工作台空数据 + 图例筛改 —— 排查与整改清单（2026-08-28）

## 一、问题现象

1. **绑定工作台看不到内容**：打开工作台只有「暂无待复核候选」，任何项目（含已有
   66 个工程对象、480 条 BOQ 的 Bengasi 项目）都出不来候选卡片。
2. **图例标定块太多不便区分**：项目聚合视图下大量块混在一起，缺少按图层/关键字
   的手动筛选手段。

## 二、根因定位

### 绑定工作台空数据 —— 不是筛选问题，是「候选无法生成」

排查过程（已实测验证）：

| 层 | 结论 | 证据 |
|---|---|---|
| 渲染层 | 卡片渲染本身正常 | 对含候选数据的项目 8/18 offscreen 实测，卡片+「依据」行均正常渲染 |
| 数据层 | 用户项目 `binding_candidate` 表 **0 条候选** | 一个真实项目 1（Bengasi）有 66 工程对象 + 480 BOQ，但候选 0 条 |
| 入口层 | **候选生成入口丢失** | `run_generate` / `extract_objects` / `run_llm_classify` 全代码库**无任何 UI 调用点** |

根因：v3 界面重设计（5f209c6）把绑定工作台原工具栏（提取/生成候选/批量确认/LLM
分类/刷新）收敛为公开方法 `run_*`，注释宣称「由顶栏 AI/更多 菜单调用——功能不丢」，
但**重设计时菜单接线被遗漏**：顶栏「AI 算量▾」菜单只有 识别当前图纸 / 批量识别 /
从文件夹导入，从未挂上 提取工程对象 / 生成绑定候选 / LLM 补充分类。于是候选流水线
在 UI 上彻底消失 → 永远无法生成候选 → 工作台永远空。
（AI 算量 takeoff 是另一条独立流水线，不产工程对象/绑定候选。）

### 图例标定缺手动筛选

- 已有：图纸筛选（cmb_sheet）、仅看未标定、隐藏建筑块、底图减法。
- 缺失：按 INSERT 图层筛选、按关键字（块名/类别/设备类型/规格）搜索。
