# 算量技术方案比选与「ezdwg + ezdxf」双引擎矢量原生改造方案

> 结合现有 `cad-boq-tool` 项目的实际痛点，对「矢量原生」路线做深入比选，
> 并给出提升正确率、引入人工标定闭环的改造方案。
> 视角：技术选型 + 现有代码改造 + 人机协作闭环。

---

## 一、结论先行

**推荐：以「路线 A：矢量原生（ezdwg + ezdxf 双引擎）」为主干，叠加「人工标定闭环」与「LLM 语义辅助」，
对现有 `cad-boq-tool` 做增量改造，而非推倒重来。**

理由：
1. 项目**已经用 ezdxf（DXF）+ ezdwg（DWG）完成解析、图层/块索引、几何计量**，矢量路线的地基已具备。
2. 医院 MEP 图纸以 2D 施工图为主，矢量原生坐标无损、可回写、可审计，最契合"算量要可追溯"的诉求。
3. 现有项目最大的正确率瓶颈**不在解析层，而在"语义识别层"**（图层/块 → 专业/系统/规格），
   这正是本次改造要重点强化的部分。
4. 栅格视觉（YOLO）与 IFC/BIM 作为**补充路线**，仅在特定场景（符号计数、已有 BIM）启用。

### 1.1 为什么是「双引擎」而非单一 ezdxf

医院图纸大量为 **DWG** 格式。若只依赖 ezdxf，DWG 必须先经 **ODA File Converter** 转成 DXF，
大图转换需 **20-40 秒**，且存在转换损耗。而 **ezdwg（Rust 内核）可直读 DWG**，秒级完成。

| 引擎 | 格式 | 实现 | 角色 |
|------|------|------|------|
| **ezdxf** | DXF（R12-R2018） | 纯 Python | DXF 默认后端，成熟稳定 |
| **ezdwg** | DWG（R14-R2018） | Rust 内核 | DWG 直读，省去 ODA 转换 |

两者通过 `app/cad/reader.py` 的 `_EntityWrapper` 统一接口，**上层代码（几何/计量/绑定）完全不用改**。
因此本方案的改造点对两个后端**同时生效**。

## 二、三条技术路线比选（结合本项目现状）

| 维度 | A 矢量原生（ezdwg+ezdxf） | B 栅格视觉（YOLOplan） | C IFC/BIM 原生 |
|---|---|---|---|
| 本项目现状 | ✅ **已落地**：`app/cad/reader.py` 双引擎，`app/measure.py` 确定性计量 | ❌ 未接入 | ❌ 未接入 |
| 精度 | 高（坐标无损，误差<0.5%） | 中（依赖分辨率，栅格化损耗） | 最高（模型即真值） |
| 对医院 MEP 适配 | 强（2D 施工图普遍） | 强（符号计数型） | 最强（但医院常只有 2D） |
| 工程速度 | 中（需图层/块规范） | 快（分钟级批量） | 快（若已有 IFC） |
| 开源许可 | ✅ ezdxf MIT / ezdwg 需确认，商用友好 | ⚠️ AGPL-3.0 传染性 | ⚠️ LGPL/GPL 混合 |
| 人工介入点 | 图层映射规则、块属性校准 | 标注样本、误检校正 | 模型合规、属性补全 |
| 与现有代码复用 | **最高**（直接改造） | 低（需新引入检测栈） | 低（需新引入 IFC 栈） |

### 2.1 为什么优先矢量原生（ezdwg+ezdxf）而非 YOLO

- **坐标与长度精度**：医院算量大量是"管线长度、设备数量"，矢量原生直接取几何长度，误差 <0.5%；栅格化后长度靠像素比例换算，误差放大。
- **可审计性**：矢量原生每个数量可追溯到 `entity.handle` + 图层 + 块，符合"每次算量可追溯审计日志"的验收标准；栅格检测只能给"检测框 + 置信度"，难以精确回写原坐标系。
- **许可风险**：YOLOplan/Ultralytics 为 AGPL-3.0，对内 SaaS 有开源义务；ezdxf 为 MIT，零风险。
- **改造成本**：本项目解析层已就绪，改造集中在"语义识别 + 人工闭环"，比引入整套视觉栈省力得多。

### 2.2 何时补充栅格/IFC

- **栅格（B）**：当图纸是**扫描件/PDF 图片**（无矢量数据）时，才需要 YOLO 检测符号计数。
- **IFC（C）**：当医院交付 IFC/BIM 模型时，直接走 IfcOpenShell 提取，精度最高、最省事。

## 三、现有项目痛点分析（改造依据）

基于对 `cad-boq-tool` 代码的梳理，当前正确率瓶颈集中在以下环节：

### 痛点 1：语义识别依赖"关键词规则"，脆弱且易误判
- `app/engineering/classifier.py` 用 `BUILDING_BG_KEYWORDS`、`ELV_SYSTEM_RULES`、`DISCIPLINE_LAYER_RULES` 等**硬编码关键词**判断专业/系统/背景。
- 问题：
  - 医院图纸图层/块命名**高度定制**，关键词覆盖不全 → 漏识别。
  - 短关键词误判（如 `TV` 误伤 `CCTV`，代码里已专门打补丁规避，说明这类问题真实存在）。
  - 关键词规则**不可学习**，每来一个新医院/新专业都要手工加规则。

### 3.2 图层/块分类依赖"项目级白名单"，配置成本高

`app/engineering/extractor.py` 的 `_resolve_layer_category` 依赖用户在「项目设置」里手工把图层归到 4 个桶（设备/导线/面积/跳过）。
- 问题：**配置工作量大**，且未配置时退化到"默认设备/默认线性"，容易把建筑背景误当设备。

### 3.3 规格/型号提取薄弱

- `infer_spec_from_block` 与 `extract_typical_sizes` 只能从块名/图层名**正则抽取**规格（如 `4MP`、`DN100`）。
- 问题：**块属性（ATTRIB）未充分利用**——很多设备型号、口径、材质存在 INSERT 的 ATTRIB 里，当前未解析，导致规格缺失、BOQ 匹配不准。

### 3.4 绑定候选依赖 Embedding + LLM，但召回子集质量决定上限

- `app/binding/matcher.py` 的 LLM 模式：Embedding 语义召回 → LLM 重排。
- 问题：**Embedding 召回子集的质量**决定了 LLM 分析的上限。若召回子集里没有正确 BOQ，LLM 再强也选不出对的。而 Embedding 召回依赖 `eo_text` 拼接质量，规格缺失会直接拉低召回。

### 3.5 缺少"人工标定闭环"与"难例挖掘"

- 现有 `reviewer.py` 支持人工确认/拒绝候选，但**没有把人工校正沉淀为可复用资产**（图例符号库、图层映射规则、规格库）。
- 问题：**每次新项目都要重新配置、重新校正**，无法"越用越准"。

### 3.6 计量规则与单位推断依赖人工

- `app/measure.py` 的 `compute_entity_qty` 依赖 `item.rule_type`（count/length/area）与 `scale_factor`，这些**默认靠人工设置**。
- 问题：设备/线性/面积三类对象的计量规则**本可从几何自动推断**（如 INSERT→count、LINE→length、闭合 LWPOLYLINE→area），但当前未充分利用。

## 四、矢量原生改造方案（提升正确率）

### 4.1 总体架构（增量改造）

```
DWG ──┐
      ├─ ezdwg 直读（Rust，快）┐
DXF ──┘                        ├─ reader.py 统一接口（已有）
      └─ ezdxf 解析（Python）─┘
       ├─ ① 块属性(ATTRIB)解析 ← 新增：规格/型号/材质 直接入库
       ├─ ② 几何类型→计量规则自动推断 ← 新增：INSERT→count / LINE→length / 闭合→area
       ├─ ③ 语义分类升级 ← 改造：规则 + 图例库 + LLM 三重判定
       │      ├─ 规则层：现有关键词（保留，作为快速通道）
       │      ├─ 知识库层：人工标定的图例符号库/图层映射库（新增，可学习）
       │      └─ LLM 层：规则/知识库不确定时，交给大模型分析（已有 llm_matcher）
       ├─ ④ 候选生成（已有 matcher.py，LLM 模式）
       └─ ⑤ 人工标定闭环（新增）：确认/拒绝 → 沉淀知识库 → 主动学习难例
```

> **双引擎说明**：改造点 ①-⑤ 均作用于 `_EntityWrapper` 统一接口之上，
> 对 ezdxf（DXF）与 ezdwg（DWG）两个后端**同时生效**，无需分别实现。
> ezdwg 已知边界（Rust panic、非 UTF-8 编码乱码、部分 R2018 压缩流）已在
> `reader.py` 的 Phase 25/26 处理，改造时需保持这些兼容逻辑。

### 4.2 改造点 1：块属性（ATTRIB）解析 —— 提升规格/型号精度

**现状**：`cad_parser.py` 的 INSERT 分支只取 `block_name/insert/scale/rotation`，**丢弃了块内 ATTRIB**。

**改造**：解析 INSERT 时读取其 ATTRIB 子实体，把 `tag=value` 存入 `blocks_json` 或新增字段。
需兼容双后端：ezdxf 用 `entity.attribs`，ezdwg 需从 INSERT 的附加实体读取。

```python
# app/cad/cad_parser.py  INSERT 分支增强（经 _EntityWrapper 统一）
elif etype == "INSERT":
    ins = _vec2(entity.dxf.insert)
    block_name = entity.dxf.name
    attribs = {}
    try:
        for a in entity.attribs:          # ezdxf: INSERT.attribs
            attribs[a.dxf.tag] = a.dxf.text
    except Exception:
        pass
    g.update({"block": block_name, "insert": ins, "attribs": attribs, ...})
```

**收益**：设备型号/规格/材质从块属性直接拿到，`infer_spec_from_block` 的兜底正则不再依赖块名猜测，**规格识别率大幅提升**，进而提升 Embedding 召回与 LLM 匹配精度。

### 4.3 改造点 2：几何类型 → 计量规则自动推断

**现状**：`measure.py` 依赖人工设置的 `rule_type`。

**目标**：从实体几何自动推断默认计量规则，人工只需复核：
- `INSERT`（块）→ `count`（数量）
- `LINE/LWPOLYLINE(开)/ARC/SPLINE` → `length`（长度）
- `CIRCLE/闭合 LWPOLYLINE/HATCH` → `area`（面积）

**实现**：在 `extractor.py` 生成 `EngineeringObject` 时，根据聚合的实体几何类型自动填 `quantity_rule`，人工在绑定工作台复核即可。

### 4.4 改造点 3：语义分类三重兜底（规则 → 知识库 → LLM）

**现状**：`classifier.py` 只有硬编码关键词规则。

**目标**：新增"知识库层"，作为规则与 LLM 之间的缓冲：

```
分类判定顺序：
  1. 规则层（现有关键词，快、确定）→ 命中即用
  2. 知识库层（人工标定的 图层映射/块→专业/块→规格 库）→ 命中即用
  3. LLM 层（规则+知识库都不确定时，交给大模型分类）→ 结果回写知识库
```

**知识库表设计**（新增，可学习）：
- `symbol_library`：`{block_name/layer_name, discipline, system, spec, unit, quantity_rule, confirmed_by, confirmed_at}`
- 人工在绑定工作台确认/拒绝时，自动写入/更新该库。

### 4.5 改造点 4：Embedding 召回子集质量增强

**现状**：`matcher.py` 的 `_boq_top_n_for_llm` 用 `eo_text` 拼接做关键词交集兜底，`embedding_matcher.py` 用 `eo_text` 做向量召回。

**目标**：把 `eo_text` 从"块名/图层/系统/规格"扩展为**包含块属性（ATTRIB）与知识库规格**的富文本，提升召回子集命中真实 BOQ 的概率。

### 4.6 改造点 5：人工标定闭环（HITL）与主动学习

**现状**：`reviewer.py` 确认/拒绝后只改候选状态，**不沉淀知识**。

**目标**：把"人工校正"变成"可复用的资产"：

```
1. 预标注：规则/知识库/LLM 产出候选（自动）
2. 人工校正：绑定工作台确认/拒绝（已有）
3. 沉淀：确认结果写入 symbol_library / layer_rules / spec_library
4. 主动学习：低置信度候选自动排队，提示人工优先复核（难例挖掘）
5. 复用：新项目/新图纸自动套用已沉淀知识库 → 精度螺旋上升
```

## 五、改造优先级与里程碑

| 阶段 | 目标 | 关键动作 | 周期(估) |
|------|------|----------|----------|
| P0 | 打通块属性解析 | 解析 ATTRIB → 规格入库，提升规格识别 | 1 周 |

| P2 | 知识库层 | symbol_library 表 + 确认/拒绝沉淀 | 2 周 |

| P4 | 主动学习难例挖掘 | 低置信度优先复核 + 复用 | 2 周 |

## 六、风险与验收标准

### 6.1 主要风险
1. **块属性缺失**：部分图纸块无 ATTRIB，需保留 `infer_spec_from_block` 兜底。
2. **图层命名混乱**：医院图纸图层不统一，知识库需"每院/每专业"积累，前期人力投入大。
3. **LLM 依赖**：LLM 分类需本机 Ollama 可用；不可用时退化为规则+知识库。
4. **ezdwg 边界**：部分 DWG（R2018 压缩流、非 UTF-8 编码）ezdwg 无法直读，需回退 ODA 转 DXF；
   改造时保持 `reader.py` 的 fallback 逻辑，不因新增 ATTRIB 解析破坏兼容。

### 6.2 验收标准（建议阈值）
- 关键设备（风机/水泵/配电箱/末端）**召回率 ≥ 95%**，误报率 ≤ 3%。
- 管线长度相对人工抽量**误差 ≤ 2%**（矢量路线目标 <0.5%）。
- 规格识别准确率（含块属性）**≥ 90%**。
- 每次算量产出**可追溯审计日志**（图源/模型版本/校正人）。

## 七、结论

**以 ezdxf 矢量原生为主干，叠加"块属性解析 + 计量规则自动推断 + 语义分类三重兜底 + 人工标定闭环"，
在现有 `cad-boq-tool` 上做增量改造，是提升正确率、控制成本、保证可追溯的最优路径。**

栅格视觉（YOLO）与 IFC/BIM 作为**补充路线**，仅在"扫描件无矢量"或"已有 BIM 模型"时启用，不改变主架构。
